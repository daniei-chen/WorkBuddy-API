# 活动任务：按任务聚合的摘要

Issue #189。账号页「活动任务」弹窗以前只回显上游 `task_runner.py` 的原始 stdout，
一行一个动作、任务名是 `Sequential_Tasks_2` 这类内部标识 —— 用户原话是「纯单词，
不知道做了什么任务、哪些没做」。

现在弹窗默认按**任务**列一列：

```
夜猫对话（23–08）              待处理
query 3/5 -> 可点亮 … dry-run 跳过

小程序选中专家并对话            已领取
1/1 -> claimed（本轮已入账）
```

右上角可切到「原文」——原始日志**一字不改**地留着（出问题要拿它跟上游对账）。

## 四档状态

| 状态 | 含义 | 典型行尾 |
|---|---|---|
| 已领取 | 奖励到手 | `已领，跳过` / `已完成/已领` / `claimed（本轮已入账）` |
| 待处理 | 还有事可做 | `可点亮` / `可领(claim)` / `未 completed` / `未达 target` / `locked` / `in_progress` |
| 跳过 | 这次不必做 | `非映射任务` / `不可伪造` / `无可用对象 id` / `未登记生效` / `skip` |
| 失败 | 出错 | 任何带「失败」的行（`buddy5 失败 -> 降级单发` 除外 —— 那是降级成功） |

一条任务常打出多行（query → accept → report → claim）。聚合取**结论最重**的那档：
失败 > 已领取 > 待处理 > 跳过；展示顺序则是失败 → 待处理 → 已领取 → 跳过
（用户最关心「还剩哪些没做」，已领取的看一眼就够）。

认不出的行按「待处理」处理并原样展示 —— 上游随时会加新文案，宁可多看一眼，
也不能谎报完成。

## 为什么分类在后端、翻译在前端

「这个任务到底做完了没有」是**领域判断**，放后端能用真实日志样本写用例
（`server/tests/test_task_summary.py`）；而这句话怎么说是**文案**，走既有的逐行译文
（`web/lib/i18n/taskrun.ts`），五种语言共用一套规则。后端只回机器可读的
`{code, state, line, count}`，不返回译好的句子（否则同一句话要在两处维护）。

任务码 → 中文名/英文名的对应表在 `web/lib/i18n/taskname.ts`：上游脚本没有机器可读的
「码 → 名称」输出（名字只写在它自己的注释里），所以这张表只能手维护；**认不出的码
原样显示**，不会因为不认识就吞掉一行。

## 没做的部分

「任务」页（全量一键执行）仍然只显示原文 —— 这次改的是用户指出的位置（账号页 →
活动任务）。两处的回显是同一个组件族，需要时可以同样接上。
