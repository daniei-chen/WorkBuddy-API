# 界面多语言（i18n）

管理端支持 **简体中文 / 繁體中文 / English / 日本語 / 한국어** 五种界面语言，
默认跟随浏览器语言，用户可在页面右上角随时切换（选择记在 `localStorage`）。

## 为什么是「客户端切换 + 无路由前缀」

前端是 `next build` 静态导出、由 FastAPI 直接托管文件。加 `/en/...` 这类语言段
意味着要改所有跳转与后端静态路由，而管理端的语言偏好本来就是**单个使用者**的
本地设置。客户端切换因此更贴合，也不影响既有部署方式。

代价：静态 HTML 永远是源语言，非中文用户整页加载时会闪一下中文（站内跳转不会，
因为 Provider 挂在根布局上不重挂）。这是与版本（realm）切换一致的取舍——两者都
避免「服务端首帧与客户端不一致」的水合报错。

## 目录与文件

| 路径 | 作用 |
|---|---|
| `web/lib/i18n/config.ts` | 语言清单、母语名称、浏览器语言识别 |
| `web/lib/i18n/index.ts` | 取值内核：键名解析、`{占位符}` 插值、复数、短语表 |
| `web/lib/i18n/provider.tsx` | `I18nProvider` / `useI18n()` / `useT()` |
| `web/lib/i18n/rich-text.tsx` | 把译文里的 `**加粗**` / `` `代码` `` 渲染出来 |
| `web/lib/i18n/locales/*.json` | 五种语言的字典（`zh-CN` 是源语言） |
| `web/components/common/layout/LanguageToggle.tsx` | 右上角语言切换器 |
| `dev/i18n-scan.mjs` | 扫描前端里还剩哪些硬编码文案（按文件统计） |
| `dev/i18n-verify.mjs` | 真浏览器逐语言、逐页取可见文本，报告残留中文 |
| `server/tests/test_web_i18n.py` | 字典结构守卫（键集、占位符、空值、英文残留汉字） |

## 两种取值方式，别混用

1. **键名**（绝大多数场景）：组件里 `const t = useT()`，取 `t('accounts.title')`；
   纯函数（如 `lib/format.ts`）用模块级的 `t()`，它跟随当前语言。
2. **短语表**（大块数据表）：`tp('每天自动领取免费额度；签到时的余额查询还能解冻被冷却的账号')`
   ——键是**中文原文**，gettext 风格。用于设置页那些与上游 `config.json` 一一对应、
   上百条的配置项 label / desc / caution：省掉一层「键名 ↔ 文案」映射，新加上游
   字段时照抄原文即可。查不到时原样返回中文，不会显示成键名或空白。

同一个短语表也用于**后端返回的文案**：`lib/api.ts` 的错误提取会过一遍 `tp()`，
因此服务端的报错、签到结果这类固定文案也能跟随界面语言（未收录的保持中文原文）。

## 加一门语言

1. 在 `web/lib/i18n/locales/` 复制 `en.json` 为 `<locale>.json`，逐条翻译；
2. 在 `web/lib/i18n/config.ts` 的 `LOCALES` 与 `LOCALE_LABELS` 里登记；
3. 在 `web/lib/i18n/index.ts` 的 `DICTS` 里 import 并挂上；
4. 在 `server/tests/test_web_i18n.py` 的 `_LOCALES` 里加上该语言；
5. 跑守门测试与验收脚本：

```bash
python -m unittest server.tests.test_web_i18n     # 键集/占位符/残留中文
node dev/i18n-scan.mjs                            # 还剩多少硬编码文案
node dev/i18n-verify.mjs <locale>                 # 真浏览器逐页验收（需 playwright-core）
```

## 不会被翻译的内容（有意为之）

这些内容属于**数据**而不是界面文案，硬翻会出问题：

- **上游生成的动态文本**：签到 / 猫猫旅行 / 活跃上报的结果行由
  `server/services/tasklog.py` 在展示层把上游英文日志转成中文，含数字的模板句
  （如「领奖成功：第 12 次行程，获得 100 积分」）保持中文原文；固定文案已进短语表。
- **CHANGELOG 正文**：更新日志条目按仓库里写的中文原样展示（翻译它等于改文档本身）；
  分类标题（安全 / 新增 / 修复…）已本地化。
- **「成长任务一键执行」面板的输出行**：回显的是上游脚本 `task_runner.py` 的原始
  stdout（连同数据库里存的历史摘要），存储与上游脚本都保持中文原文；界面由
  `web/lib/i18n/taskrun.ts` 在**展示层**按「模板 → 译文」逐行重排，
  **未命中的行原样输出** —— 上游加大日志量时最坏是继续显示中文，不会丢日志。
  （`dev/i18n-scan.mjs` 会把该文件里的中文计入统计：那是匹配上游原文用的模式串，
  不是待翻译的界面文案。）
- **模型系列名、任务类型、审计动作、地区名**等后端枚举：界面按**枚举值**取译文，
  认不出的值回退显示后端给的名字，不会显示成空。
- **开发者可见的异常**（如 `useRealm 必须在 RealmProvider 内使用`）、代码注释、
  `package.json` / 配置项键名等技术标识。

## 已知取舍

- 五种语言的字典都会打进前端包（约 +100 KB，gzip 后更小）。若要支持更多语言，
  建议改为按需加载语言包。
- 站点 metadata（`description`）是构建期写死的英文——它无法跟随运行时切换，
  见 `web/app/layout.tsx` 的注释。

## 图标清晰度（与本目录相邻的一处教训）

多语言改造时顺带修掉了一个长期存在的问题：**按钮里的图标又大又糊**。
根因不在图标本身，而是按钮尺寸类里的转义写法编出了永远匹配不上的选择器，
图标一直按 lucide 默认的 24px 渲染。相关说明与实测数据在：

- `web/app/globals.css` 中「按钮内图标的尺寸与清晰度」注释（含一次走偏的记录）；
- `dev/icon-probe.mjs`（量尺寸 / 描边 / 设备像素比，`--assert` 可作门禁）；
- `dev/icon-ab.mjs`（在**真实页面**上并排渲染多组参数，供肉眼比对）。

修复方式刻意保持最小：只把尺寸改回 16px，描边与渲染方式沿用 lucide 默认，
从而与底部工具栏图标（公认清晰的基准）参数完全一致。

**别再用自造像素指标判断图标清晰度。** 这次踩过的坑：为了让「实心黑 / 中间灰像素比」
好看，加了 `shape-rendering: crispEdges` 与更粗的描边，指标大幅提升但曲线图标
（如 `hand-coins`）糊成色块。原因是该指标奖励「灰像素少」，而关掉抗锯齿恰好
让灰像素归零——指标被自己的改动带偏了。

改动这类全局样式后，建议跑一遍 `node dev/ui-shots.mjs` 肉眼扫各页，
再用 `node dev/icon-probe.mjs --assert` 确认尺寸没被改坏。
